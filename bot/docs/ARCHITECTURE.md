# `agy-telegram-rs` — Security & Production Architecture Specification

## 1. Crate Dependency DAG
- `agy-core`: zero internal deps — typed `BridgeError`, Bot API 10.4 wire structs (`tg`), `Config`, `atomic` (`0600` temp-file swap), `StateStore` (`state.json`), `AclStore` (`acl.json`), `AccountStore` (`accounts.json`, 5h/7d usage ledger, 1% weekly reserve, `AccountPolicy`, `PoolBreakerState`), `ProxyRegistry` (`proxies.json`, 1:1 sticky bindings, `FailClosed`/`FallbackDirect`), `OutQueue` (`outqueue.json`), `HealthTracker` (`health.json`).
- `agy-render`: depends on `agy-core` — GFM Markdown -> Telegram HTML converter, UTF-16 tag-balanced `split_html`, block/fence-aware `split_markdown`, `PremiumState` (`RestrictedEmoji` 17 vetted IDs + `$STATE_DIR/emoji.json` overlay + graceful degradation).
- `agy-net`: depends on `agy-core` — `ProxyPool` (HTTP/HTTPS/SOCKS5/Direct, circuit breaker, latency EWMA, failover/round-robin/race), `probe_proxy_route` (TLS/HTTP 204 health prober) & `Retry-After` parser, `BotApiClient` (`rustls-tls`, JSON preserving empty `""`, multipart uploads, 429 `retry_after`, AWS full-jitter), `Poller` (safe `offset` commit, dedupe, watchdog kick, constant-time webhook secret verifier), Linux `sd_notify` + `Watchdog`.
- `agy-ext`: depends on `agy-core` — Async Tokio stdio MCP JSON-RPC 2.0 client (fixes blocking Python Popen), SkillPort/Catalog/Installed skills YAML CRUD, `mcp_config.json` secret-masked CRUD (`••••••••`), AI-Memory bridge, Multi-Engine `EngineRunner` (`agy` NDJSON streaming + pluggable runners) with `pgid` `SIGINT -> SIGTERM -> SIGKILL` cancellation.
- `agy-widgets`: depends on `agy-core`, `agy-render`, `agy-net` — Bot API 10.4 Profile-1 CSS/JS/HTML minifier & linter, `zlib-9` byte counter (`<= 4096 B` / `<= 32768 B`), `<tg-widget>`/`.widget.html`/`.widget.json` parsers, `WidgetStore` (`widgets.json` + legacy purge), 4 Apple-HIG widgets (`skills`, `mcp`, `models`, `memory`), In-Bubble Rich Card renderer, HMAC-SHA256 `initData` verifier, `Axum` WebApp Server.
- `agy-bot`: depends on all 5 library crates — `Axum` unified HTTP server (`/healthz`, `/w/{wid}`, `/api/w/{wid}/*`, `/tg/webhook`), Transport supervisor (`polling`/`webhook`/`auto`), Auth gate, Cron & Sync scheduler (`cron_jobs.json`), Updater & `--check`/`--health`/`--bench-ab` CLI, complete command/callback/widget/text handlers.

## 2. Security Controls Traceability
- **T1 (Unauthorized access / probing):** Non-private chats and unapproved users receive ZERO replies (`AuthMiddleware` silent drop); only private `/start` notifies `OWNER_ID` with 300s cooldown; blocked users never re-notify.
- **T2 (Webhook spoofing):** `POST /tg/webhook` verifies `X-Telegram-Bot-Api-Secret-Token` with `subtle::ConstantTimeEq`.
- **T3 (WebApp forging/replay):** `verify_webapp_init_data` enforces `WebAppData` HMAC-SHA256, rejects duplicate keys, checks `auth_date <= 86400s`, verifies numeric UID against live `AclStore::approved_ids()`.
- **T4 (Secret leakage in logs/MCP/diffs):** `Config::Debug`, `ProxyRoute::safe_label`, `redact_secrets_in_text`, and `MASKED_SECRET = "••••••••"` secret restoration prevent token/key exposure.
- **T5 (Privilege escalation via `/cwd`, `skip_permissions`, MCP install):** Enforced against `AclStore::has_perm` (`skills_manage`, `mcp_manage`, `root_access`) plus explicit Owner approval for AI MCP installation; owner status/permissions immutable.
- **T6 (AI runaway loops & tool bursts):** `AgyStreamGuard` inspects live `agy` NDJSON `step_update` tool calls (with `step_index` dedup and target signatures), issuing clean `SIGINT -> SIGTERM -> SIGKILL` without penalizing or rotating accounts.
- **T7 (HTTP/Telegram DDoS, `/start` disk flood, OOM & outbox secret leaks):** `http_guard` enforces bounded per-IP rate limits (trusting proxy headers only from loopback), concurrency cap (`503`), request timeout (`408`), and full security headers (`Referrer-Policy`, `Permissions-Policy`, Telegram `frame-ancestors`); `WebAppState` enforces per-UID `/api/w/*` rate limits; `dispatch_update` applies per-UID anti-flood (exempting `/stop`); `AclStore` caps pending strangers (`ACL_MAX_PENDING`) and debounces `/start` spam flushes; `JobManager` enforces `MAX_GLOBAL_AI_JOBS`; `RenderBridge` scans outbox files via `agy_core::security::scan_file_for_secrets` before upload.

## 3. Cutover & Rollback Strategy
1. Keep `/opt/agy-telegram/app` (Python v3) active throughout all Rust builds, unit/integration tests, and A/B benchmarks.
2. Verified Python backup & clean ZIP archived at `/opt/agy-telegram/backups/agy-telegram-python-v3-backup.zip` (+ directory `/opt/agy-telegram/backups/python-v3-20261118`).
3. Stage release binary at `/opt/agy-telegram/bin/agy-telegram` and run pre-flight `--check` before systemd unit update.
4. Schedule detached post-turn restart (`post_turn_restart.sh`) verifying `systemctl is-active`, `:8787/healthz`, Caddy HTTPS `/healthz`, `healthcheck.sh`, and rolling back service unit + Python app automatically on failure.
- **P4 (Token hygiene & local autonomy):** Resumed turns use compact 1-line bridge headers (`PROMPT_COMPACT_RESUME`), `turn_profile` classifies `lite`/`standard`/`full` without altering MCPs/skills/`.md`, `local_fast` answers unambiguous ping/time/status/math queries locally in Rust with strict RBAC (0 AI tokens), `McpClientPool` caches verified read-only MCP calls (`MCP_RO_CACHE_TTL_SECS=45`) with instant write invalidation, `BotCtx::mcp_rows_live` caches 30s with mutation invalidation, and `agent_runtime` applies 16 KiB head+tail early compaction (`AGENT_TOOL_OUTPUT_MAX_BYTES`).
